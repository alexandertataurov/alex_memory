# AM-074 — Safe Derived-State Repair

## Objective

Provide an explicit, bounded, resumable repair workflow for derived state only.
It must report scope before mutation, preserve established authority, and make
a completed second run a no-op.

## Current state

The repository has bounded helpers for FTS rebuild, task-to-project linkage,
conversation segments, project health, and materialized-context refresh. There
is no shared inventory, dry-run report, checkpoint, or apply ordering.

## Authority

| Scope | Input | Output | Boundary |
| --- | --- | --- | --- |
| FTS | current canonical rows | FTS indexes | rebuildable only |
| Task-project links | accepted observations | task link and segments | never overwrite an existing link |
| Project health | dated canonical state | health and follow-ups | no source mutation |
| Context | canonical rows plus invalidations | materialized state | explicit bounded scopes |

## Constraints

- Development and tests use isolated SQLite fixtures only.
- Operator execution requires read-only verification, review of dry-run counts,
  a SQLite recovery copy, and distinct apply authorization.
- Exclude graph improver work until AM-109 proves temporal-local authority.
- Exclude profile refresh because it can use a provider.
- Prove finite limits, source/manual invariants, exact restart state, and a
  second zero-work run on fixtures.

## Delivery sequence

1. Add read-only inventory counts for explicit operation names; unsupported
   scopes must fail closed.
2. Add dry-run with finite limits and a deterministic run identity; no writes.
3. Add an append-only run ledger only where existing idempotency cannot prove
   restart safety. A restart must name the exact unfinished unit.
4. Add apply only after fixture proof, explicit operator confirmation, matching
   dry-run identity, and finite limits; record before/after counts and failure.
