# Durable Notion write-back

Use this after work that produced a confirmed architecture/product decision,
major implementation completion, changed requirement, validated/refuted
assumption, material blocker, useful follow-up, or technical debt worth
tracking. Do not write terminal output, routine test results, every modified
file, debugging traces, intermediate reasoning, speculative ideas, or duplicate
tasks.

Before writing, search for the existing project, decision, or task and update
the appropriate object instead of creating a duplicate. Persist a concise,
source-grounded change/status and any necessary links or next action. Confirm
the target and summarize what changed. If write access is unavailable, report
the failure once and leave repository work intact.
